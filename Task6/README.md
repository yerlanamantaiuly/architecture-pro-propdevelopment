# Task 6. Аудит активности пользователей и обнаружение инцидентов

Включаем audit-логирование на kube-apiserver, прогоняем «атакующий»
сценарий, фильтруем лог и пишем отчёт по инциденту.

## Сданные артефакты (из ТЗ)

| Файл | Что это |
| ---- | ------- |
| `analysis.md` | Краткий отчёт по выявленным событиям |
| `audit-extract.json` | Выжимка из audit.log с подозрительными событиями |
| `analyze-audit.sh` | Скрипт фильтрации audit.log (Bash + jq) |

## Поддерживающие файлы

| Файл | Назначение |
| ---- | ---------- |
| `audit-policy.yaml` | Policy, которую читает apiserver. Скорректирована относительно ТЗ — см. README ниже |
| `setup-audit.sh` | Включает аудит в Minikube: копирует policy, патчит static pod kube-apiserver |
| `simulate-incident.sh` | Симуляция активности из ТЗ |
| `audit.log` | Выгруженный лог из Minikube (для воспроизводимости анализа) |

## Запуск с нуля

```bash
cd Task6
./setup-audit.sh         # включает аудит (требует minikube)
./simulate-incident.sh   # генерирует подозрительные действия
./analyze-audit.sh       # фильтрует, кладёт audit-extract.json
```

После последнего шага сам отчёт `analysis.md` обновляется вручную, опираясь
на сводку из stdout и на содержимое `audit-extract.json`.

## Замечания по policy

В ТЗ во втором правиле policy указано `group: "*"`, но это значение не
проходит валидацию API-сервера (схема требует RFC 1123 subdomain). Чтобы
получить тот же эффект catch-all-Metadata-логирования, в нашей policy
второе правило идёт **без блока `resources`** — без него правило применяется
ко всем ресурсам, которые не подпали под первое правило. Поведение
эквивалентно, и apiserver успешно стартует.

## Как лог попадает наружу из Minikube

Apiserver в Minikube — статический под. Чтобы он мог писать аудит-лог на
ноду, `setup-audit.sh` патчит `/etc/kubernetes/manifests/kube-apiserver.yaml`:

- добавляет args `--audit-policy-file` и `--audit-log-path`;
- добавляет volumeMount-ы: каталог с policy и сам файл лога;
- добавляет соответствующие volumes (hostPath).

Это идемпотентно: повторный запуск ничего не дублирует.
