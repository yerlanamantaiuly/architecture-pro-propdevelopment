# PropDevelopment Security Lab

Учебная лаборатория к 5-му спринту Yandex Practicum. Поднимает в Minikube
мини-копию ландшафта PropDevelopment с **нарочно зашитыми проблемами** из
описания кейса. Каждая проблема воспроизводится одним demo-скриптом — это
точка отсчёта, из которой потом, в Task1–Task7, эти проблемы закрываются.

> Лаба живёт только в ветке `sprint-5`. В финальный PR на `main` она НЕ войдёт
> (отдельная договорённость с рецензентом — PR будет содержать только `Task1`…`Task7`).

## Что моделируем

| Сервис             | Роль в кейсе                                | Заложенный баг                                                 |
| ------------------ | ------------------------------------------- | -------------------------------------------------------------- |
| `client-mart-app`  | Витрина продаж + бронирование               | IDOR в `/profile` и `/bookings`: `?user_id=` без проверки сессии |
| `client-crm-app`   | CRM клиентов                                | Своя таблица `clients`, нет синка с mart → дубликаты + расхождения |
| `tenant-core-app`  | Сервисы для собственников (ЖКУ)             | Контракт `/owners/{id}/profile` отдаёт паспорт + ФИО + телефон |
| `partner-api`      | API внешней управляющей компании            | Cross-tenant: токен УК_A валиден, но получает данные УК_B      |

И на уровне кластера: `namespace propdev` поднят **без PSA, без NetworkPolicy
и с дефолтным RBAC** — это базовое уязвимое состояние, которое предстоит закрыть
в Task4–Task7.

## Запуск

Предварительно нужны: `docker` (текущий юзер в группе docker), `minikube`,
`kubectl`. Команды установки — в корневом README репозитория или в чате с Claude.

```bash
cd lab
./scripts/bootstrap.sh        # старт minikube + build + apply + seed
./demo/01-idor-leak.sh        # прогон сценариев по одному
```

Снос:

```bash
./scripts/teardown.sh         # только namespace
# или
minikube delete               # снести весь кластер
```

## Что лаба намеренно НЕ делает

- Не моделирует продакшен-надёжность БД (используем `emptyDir`, данные пропадают
  при рестарте пода — это ок, seed восстанавливается).
- Не моделирует ингресс, auth-провайдера, ALB и прочее граничное оборудование —
  фокус на внутренних потоках, которые упомянуты в кейсе.
- Пароли в DSN и токены в seed-файлах лежат в открытом виде. Это часть демонстрации —
  в Task1 они станут «секретными данными» по классификации ISO 27001/27002.
